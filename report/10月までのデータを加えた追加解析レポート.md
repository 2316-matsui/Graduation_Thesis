# 10/28 までのデータを加えた追加解析

作成日: 2026-11-22
関連資料: [再現検証レポート.md](再現検証レポート.md)、[フレーム形式検証レポート.md](フレーム形式検証レポート.md)、[CSI形式とファームウェア設定の解説.md](CSI形式とファームウェア設定の解説.md)

## 1. 目的と対象データ

これまでの解析は、技術メモが対象にした 06/18〜08/04 の 20 条件だけを使っていた。本レポートでは、08/06〜10/28 に測定された 11 条件を加えた **31 条件**で解析し直す。目的は次の 3 つである。

1. これまでの手法（技術メモ第 5 章の再現、フレーム形式の検証）を新しい 11 条件に当てはめる。
2. 新しいデータで増えた「同じ配置を別の日に測った条件」を使い、**日をまたいでも回転数を識別できるか**を調べる。
3. 日内評価の高い正解率が、回転数ではなく**測定時間帯の違い**で説明できてしまわないかを調べる。

対象外にしたデータ:
- `1019-1103_machine2_…`: 別の装置（machine2）で、回転数のクラスも異なる（0/2000/4500/…）。測定期間も 11/03 まで及ぶ。
- `1109_…`: 10/28 より後の測定。

## 2. 結論

1. **日内評価では、新しい 11 条件も高い正解率になった**（時間平均で 90.9〜99.8 %）。これまでの 20 条件と同じ傾向である（4 節）。
2. **フレーム形式と P_dir の関係は、ルータ 14 条件でも成り立った**（D・WD 形式の比率と P_dir: r = −0.955、p = 1×10⁻⁷）。形式の比率はチャネルでは決まっていなかった（5.1 節）。
3. **日をまたぐと、どの配置でも正解率はほぼ偶然（25 %）まで落ちた。** 他の日すべてで学習して残りの 1 日でテストしても同じである。ルータ条件だけでなく、全パケットが S 形式の ATOM S3 / ESP32-S3 条件でもそうなった。振幅の水準をそろえても、時間変動の特徴量を使っても、改善しなかった（6 節）。
4. **日内の正解率の多くは、測定時間帯の違いでも説明できてしまう。** 同じ回転数の 1 セッションを時間で 4 つに区切っただけの擬似クラスが、平均 70.9 % 当たった（偶然なら 25 %）。また、各クラスの前のほうのファイルで学習して後ろのほうのファイルでテストすると、正解率は平均 95.2 % から 76.3 % に下がった。31 条件中 13 条件では 20 pt 以上下がった（7 節）。
5. 振幅の水準（ゲイン）の違いは原因ではなかった。セッションごとに違っていたのは、**サブキャリアごとの振幅の形**だった（8 節）。

**まとめ:** 現在の測定のやり方（1 つの回転数を 1 回の連続測定でまとめて取る）と評価のやり方（ファイル単位のランダム分割）では、「回転数を識別できている」ことと「測定セッションを見分けている」ことを区別できない。[フレーム形式検証レポート.md](フレーム形式検証レポート.md) の「回転数の情報は実際に CSI に含まれている」という結論は、フレーム形式という要因を除いたという意味では正しい。しかし、**セッションの違いという要因を除いたものではない**。今回の結果は、日内の高精度の大部分がセッションの違いによる可能性を強く示している。回転数の情報があるかどうかは、測定の設計を変えて確かめる必要がある（10 節）。

### 5.2 P_dir との関係（ルータ 14 条件）

| 条件 | D+WD 形式の比率 | P_dir |
|---|---|---|
| 08/06 R-F→A-F | 0.7 % | 82.7 % |
| 09/07 R-F→A-N ch11 | 79.5 % | 44.1 % |
| 09/08 R-F→A-N ch11 | 26.4 % | 68.6 % |
| 09/10 R-F→A-N ch11 | 52.4 % | 64.5 % |

これまでの 8 条件と合わせた 14 条件で、D+WD 形式の比率と P_dir の相関は **Pearson r = −0.955（p = 1.1×10⁻⁷）、Spearman ρ = −0.943（p = 4.4×10⁻⁷）** だった。形式ごとに見ると、S・W 形式の P_dir は 69〜98 %、D・WD 形式は 10〜75 % だった。「ルータの P_dir のばらつきは、列 0 に大きな値をもつ形式の比率で決まる」という結論は、新しいデータでも成り立つ。

### 6.4 読み取れること

- **すべてのグループ・特徴量で、正解率は偶然の水準だった。** 学習に使う日を 6 日に増やしても（R-F→A-N の leave-one-day-out）、改善しない。
- 予測は、テストした日のファイルのほとんどが 1〜2 クラスに偏る形になった。例: 06/30 は cv で全ファイルを 3000 rpm と予測、09/14 は raw で 89 % のファイルを 3000 rpm と予測、10/04 は raw で 83 % のファイルを 0 rpm と予測。日の違いによる特徴量のずれが、クラスの違いよりずっと大きいということである。
- 形式の混在がない ATOM・ESP 条件でも同じなので、**日をまたげない原因はフレーム形式ではない**。
- 日をまたげないこと自体は、「設置状態（位置・向き・周囲の物）が日ごとに違うので、回転数の現れ方も日ごとに違う」ということでも起こりうる。そのため、これだけでは日内に回転数の情報がないとは言えない。これを切り分けるのが 7 節の検証である。

### 6.5 チャネルをそろえた場合

## 7. 時間ドリフトの対照テスト

### 7.1 方法

3 節のとおり、各クラスのファイルは 1 本の連続測定（1 クラスあたり約 30〜70 分）を時間順に区切ったものである。これを利用して、全 31 条件で次の 3 つを比べた（特徴量はすべて列 2〜58 の振幅の時間平均）。

| 名前 | 内容 | 意味 |
|---|---|---|
| **rpm_random** | 通常の評価。回転数 4 クラス、ファイル単位のランダム分割 | これまでのレポートの値 |
| **rpm_temporal** | 回転数 4 クラス。各クラスの時間的に前の 64 % で学習、次の 16 % で早期終了、最後の 20 % でテスト | 時間的に離れたファイルでも当たるか |
| **block_random** | 対照。同じ回転数の 1 セッションを時間順に 4 等分して擬似クラスにし、ランダム分割で識別。4 つの回転数それぞれで行って平均 | 回転数は同じなので、当たるとすれば時間変化だけによる |

|---|---|---|---|---|
| 06/18 R-N→A-N | 96.4 | 70.8 | −25.6 | 52.7 |
| 06/22 R-F→A-N | 95.7 | 61.3 | −34.4 | 69.9 |

### 7.3 読み取れること

- **回転数が同じでも、時間帯が違うだけでファイルを見分けられる**（block_random の平均 70.9 %、最大 90.8 %）。CSI の時間平均は、1 回の測定の中でもゆっくり変化している。ファイル単位のランダム分割では、学習側とテスト側のファイルが時間的に隣り合うので、この変化を手がかりにできる。
- 回転数のクラスは別々の時間帯に測っている。そのため、クラス間の時間的な隔たりは、block_random の 4 区間どうしの隔たりと同じかそれ以上である。つまり、**回転数の情報がまったくなくても、ランダム分割で 70〜90 % 程度の正解率が出てもおかしくない**。
- 時間的に離れたファイルでテストすると（rpm_temporal）、31 条件中 12 条件で 70 % 未満になった。13 条件では 20 pt 以上下がった。
- 一方、7 条件では rpm_temporal が 90 % 以上を保った（06/30 A-N→A-N、07/10、07/20、07/21 E-F→A-N、09/08、09/14、10/28）。これらの条件では、セッションの違いが時間がたっても安定して保たれている。ただし、その違いが回転数によるものか、セッションごとに一定の別の要因（設置のわずかなずれなど）によるものかは、この検証では区別できない。
- ルータ条件は block_random が最も高い（78.1 %）。ルータ条件には、時間とともに変わるフレーム形式の比率という変動要因が加わるためと考えられる。

## 8. ゲイン（振幅の水準）の影響

`app_main_router_recv.c` は、最初の 100 パケットの平均で AGC・FFT ゲインを固定する（`phy_force_rx_gain`、`phy_fft_scale_force`）。もしクラスごとに測定を起動し直しているなら、クラスごとに違うゲインで固定される。その場合、振幅の水準だけでクラスを当てられてしまう。これを確かめるため、日内評価でも特徴量を変えて比べた。

| 特徴量 | ランダム分割（31 条件の平均） | 時間方向の分割（平均） |
|---|---|---|
| raw（時間平均） | 95.2 | 76.3 |
| norm（ファイル平均で割る） | 94.7 | 75.1 |
| cv（標準偏差 ÷ 平均） | 75.4 | 61.0 |

- norm にしても正解率はほとんど変わらなかった。**振幅全体の水準（ゲイン）は主な手がかりではない。** セッションごとに違うのは、サブキャリアごとの振幅の形（周波数特性）である。
- cv（時間変動の大きさ）は、ATOM・ESP 条件では 41〜93 %（ランダム分割）と、条件によるばらつきが大きかった。回転による時間変動は、時間平均の形の違いほどはっきりした手がかりになっていない。ルータ条件の cv は高い（66〜99 %）。しかしルータ条件では、形式の混在そのものが時間変動を大きくするので、回転によるものとは言えない。

（条件ごとの値は `results/extended/within_norm.json`）

## 9. 解釈と限界

### 9.1 これまでの結論への影響

- 技術メモの「マイコン送信でもルータ送信でも、時間平均で 90 % 以上の精度で回転数を識別できる」という結果は、そのままでは**回転数を識別できている証拠にならない**。ファイル単位のランダム分割では、セッションの違い（測定時間帯の違い）を見分けるだけでも同程度の精度が出うるからである。
- [フレーム形式検証レポート.md](フレーム形式検証レポート.md) の「単一形式でも識別できるので、回転数の情報は CSI に含まれている」という結論も、同じ制約を受ける。単一形式テストで除けるのはフレーム形式という要因だけで、セッションの違いは除けない（同レポート 6.2 節 2 で「否定できないこと」として挙げていた点が、実際に大きかったことになる）。
- 一方、フレーム形式と P_dir の関係（5.2 節）は、識別とは関係のない CSI の性質なので、今回の結果の影響を受けない。

### 9.2 この検証の限界

1. **回転数の情報が「ない」とは言えない。** 今回示したのは、今のデータ・今の評価方法では、回転数の効果とセッションの効果を分けられないということである。rpm_temporal が 90 % 以上を保つ 7 条件では、何らかの安定したクラス間の違いがある。
2. **rpm_temporal は厳しすぎる可能性がある。** 回転数の情報があっても、ドリフトが大きければ、時間的な外挿で精度は下がる。
3. **block_random と回転数クラスの時間的な隔たりは同じではない。** 回転数クラスどうしの間には、測定の中断や装置の操作（回転数の変更、機器の再起動など）が入る。block_random の 4 区間は連続している。この差は、回転数クラスのほうがセッションの違いが大きくなる向きに働くと考えられる。
4. **クラスの測定順と時刻は分からない。** 各クラスを何時に、どの順で測ったかの記録がないため、隔たりの大きさを直接比べられない。
5. **日をまたいだテストでの設置状態の違い。** 同じ「近・遠」の配置でも、日ごとに位置や向きが少しずつ違う可能性がある。ch も日によって違う（ch1・ch11）が、同じ ch の日だけで比べても結果は変わらなかった（6.5 節）。

## 10. 提案

### 10.1 測定の設計（最も重要）

回転数とセッションの違いを切り離すには、測定のやり方を変える必要がある。

- **回転数を短い間隔で入れ替えて測る。** 例: 0 → 3000 → 6000 → 9000 → 0 → …を、1 回 1〜2 分ずつ、何周も繰り返す。こうすれば、各回転数が多くの時間帯に散らばり、時間変化と回転数が重ならない。
- **評価はセッション（1 回の連続測定）単位で分ける。** 学習とテストに同じセッションのファイルを混ぜない（leave-one-session-out）。
- **0 rpm を基準として何度も測る。** 0 rpm のセッションどうしの違いがどれくらいあるかが分かれば、それを超える違いが回転数によるものと言える。
- **測定の記録を残す。** 各セッションの開始時刻、順番、ファームウェアを起動し直したかどうか、ch、ルータの設定を記録する。

### 10.2 解析

- 今のデータで評価するなら、ランダム分割ではなく時間方向の分割（7 節の rpm_temporal）を基本にする。block_random を「セッションの違いだけで出る正解率」の目安として併記する。
- 回転数に物理的に結びついた特徴量を探す。3000/6000/9000 rpm は 50/100/150 Hz の回転周波数に当たり、パケットレート（ファイル全体の平均で ATOM 約 79、ESP32-S3 約 70、ルータ約 60 パケット/s）より高いので、エイリアシングした周波数に現れるはずである。CSI の時系列のスペクトルにその周波数のピークがあれば、セッションの違いでは説明できない証拠になる。→ 実施した結果、回転周波数の成分は検出されなかった（[回転周波数のスペクトル解析レポート.md](回転周波数のスペクトル解析レポート.md)）。
- ルータ条件は、引き続き形式で選別してから解析する（[フレーム形式検証レポート.md](フレーム形式検証レポート.md) 7 節）。
