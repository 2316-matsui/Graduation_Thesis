# CSI のフレーム形式とルータ受信ファームウェアの設定についての解説

作成日: 2026-11-22
関連資料: [フレーム形式検証レポート.md](フレーム形式検証レポート.md)、[フレーム種別交絡_検証レポート.md](フレーム種別交絡_検証レポート.md)
対象ファームウェア: `use_program/app_main_router_recv.c`

---

## 1. 要点

- 「パケットごとに CSI の形式が異なる」とは、**CSI 配列の何列目にどの周波数（サブキャリア）の値が入っているかが、パケットによって違う**ということである。
- `htltf_en = true` にしていても、**HT-LTF だけから CSI を取っているとは言い切れない**。理由は 4 つある（3 節）。
- 形式の違い（S と W）は、受信機の**セカンダリチャネルの設定（20 MHz で動くか 40 MHz で動くか）**による並びの違いと、よく合う（4 節、仮説）。
- 帯域幅がルータの判断で変わること自体は避けにくい。ただし、**記録して選別する**、**ルータ側で 20 MHz に固定する**ことで、解析上の問題は避けられる（5 節）。

## 2. 「パケットごとに CSI の形式が異なる」とはどういうことか

### 2.1 前提: CSI 配列

ESP32 が出力する CSI は、1 パケットあたり 64 個（列 0〜63）の複素数の配列である。各列が 1 本のサブキャリア（OFDM の周波数成分）に対応する。20 MHz 帯域のサブキャリアは周波数番号 −32〜+31 の 64 本で、実際に値があるのは −28〜+28 付近だけである。帯域の両端（ガードバンド）はヌル（値 0）になる。

重要なのは、**周波数番号と列番号の対応（並び順）は 1 通りではない**ことである。

### 2.2 見つかった並び方の違い

```
S 形式（標準）: 低い周波数 → 高い周波数 の順に並ぶ
 列:     0  1 | 2 ............ 30 ............ 58 | 59 ... 63
 周波数:  ヌル | −28 ........... 0 付近 ......... +28 | ヌル
            ↑両端にヌル。値がある列は 2〜58

W 形式（巡回）: 0 → 正の周波数 → 負の周波数 の順（FFT の出力順）
 列:     0 | 1 ....... 28 | 29〜35 付近 | 36 ....... 63
 周波数:  0 | +1 ...... +28 | ヌル（±29〜32）| −28 ...... −1
                           ↑帯域の端が配列の真ん中に来る
```

- W 形式で「列 30〜34 がすべて 0」になるのは、帯域端のヌルが配列の中央に来るためである。
- **同じ「列 10」でも、S 形式では −20 番付近、W 形式では +10 番付近のサブキャリア**を指す。物理的には別の周波数である。
- D・WD 形式は、S・W 形式に加えて**列 0 に 100〜160 程度の突出した値**をもつ（通常の値は 20 以下）。この値の意味は分かっていない。

### 2.3 なぜパケットごとに違うのか

ESP-IDF の CSI は、受信したフレームの種類によって中身の構成が変わる。

- non-HT（11a/g 形式）か HT（11n）か: 含まれるトレーニング系列（L-LTF / HT-LTF）が変わる。
- STBC の有無、帯域幅（20/40 MHz）、セカンダリチャネルの位置: 配列の長さや並びが変わる。

ATOM S3 / ESP32-S3 は毎回同じ設定で送信するので、全パケットが S 形式になる。一方、ルータ（NEC Aterm WX3000HP）は状況に応じて変調方式やフレーム形式を自動で切り替える。そのため、受信側には種類の違うフレームが混ざって届き、CSI の並びもパケットごとに変わると考えられる。

### 2.4 何が問題になるか

1. **特徴量の意味がずれる。** 現在の解析は全パケットの「列 2〜58」をそのまま特徴量にしている。そのため、S 形式と W 形式が混ざると、別の周波数の値を同じ特徴として平均・比較していることになる。
2. **交絡の原因になる。** 形式の切り替わりは測定セッション単位で起きる。一方、回転数のクラスは時間帯ごとにまとめて測っている。そのため、分類器が回転数ではなく「その時間帯に多かった形式」を手がかりにできてしまう。
3. **P_dir が下がる。** D・WD 形式の列 0 の突出値は、IFFT すると全タップに広がる。その分、CIR のピーク周辺へのエネルギーの集中度（P_dir）が下がる。ルータの P_dir が日によってばらつくのは、この形式の比率でほぼ説明できる（r = −0.958、[フレーム形式検証レポート.md](フレーム形式検証レポート.md) 5.5 節）。

## 3. `htltf_en = true` でも HT-LTF のみとは限らない理由

`app_main_router_recv.c`（ESP32-S3 などで使われる分岐）の CSI 設定は次のとおり。

```c
wifi_csi_config_t csi_config = {
    .lltf_en           = false,
    .htltf_en          = true,
    .stbc_htltf2_en    = false,
    .ltf_merge_en      = true,
    .channel_filter_en = true,
    .manu_scale        = true,
    .shift             = true,
};
```

### 3.1 この設定は「HT フレームを受けたときに、どの系列を出すか」を決めるもの

HT-LTF が存在するのは HT（11n）フレームだけである。non-HT（11a/g 形式）のフレームには L-LTF しかない。ルータは、管理フレームや低レートでの応答を non-HT で送ることがある。

`lltf_en = false` のときに non-HT フレームの CSI がどう扱われるか（コールバックが呼ばれないのか、L-LTF の値が入るのか）は、ESP-IDF のドキュメントからははっきりしない。今のコードは `rx_ctrl->sig_mode` を確認していないので、**non-HT 由来の CSI が混ざっていないことを確かめられていない**。

### 3.2 `ltf_merge_en = true` なので、純粋な HT-LTF ではない

ESP-IDF の説明では、この設定を有効にすると、HT パケットを受けたときに **L-LTF と HT-LTF を平均した値**が HT-LTF のデータとして出力される。HT-LTF をそのまま使いたい場合は `false` にする。

### 3.3 拾っているのは ping の応答だけではない

コールバックでは、送信元 MAC が BSSID と一致するかだけで選別している（`memcmp(info->mac, ctx, 6)`）。そのため、ping の応答に限らず、**ビーコンなどルータが送るすべてのフレーム**が対象になる。ビーコンは通常レガシーレートで送られる。

### 3.4 先頭 128 バイトを決め打ちで読んでいる

コールバックは、`info->len` に関係なく `info->buf[0]`〜`buf[127]` を出力している。ESP-IDF の CSI バッファは、フレーム種別やセカンダリチャネルの設定によって長さも並びも変わる。そのため、**先頭 64 サブキャリアが何を指すかはパケットによって違いうる**。先頭 4 バイトが無効かどうかを示す `first_word_invalid` も確認していない。

## 4. 形式の違いの正体についての仮説

ESP-IDF の CSI のサブキャリアの並びは、受信機のセカンダリチャネルの設定によって変わる。

| 受信側の設定 | 20 MHz 信号の並び | 今回のどの形式に近いか |
|---|---|---|
| セカンダリなし（20 MHz 動作） | 0〜31, −32〜−1（FFT 順）。帯域端のヌルが配列の中央に来る | **W 形式**と一致 |
| セカンダリあり（40 MHz 動作） | 128 点の格子の半分（0〜63 または −64〜−1）に 20 MHz 帯域がまとまって入る。両端がヌルで、中央にヌルがない | **S 形式**と一致 |

- S 形式で列 29〜34（帯域の中心付近）に値があることも、この仮説と合う。20 MHz 信号が 40 MHz の格子の中心からずれた位置に置かれれば、そうなるからである。
- esp-csi の公式サンプルでは、ESP32 どうしの通信のときに `WIFI_SECOND_CHAN_BELOW` を指定するのが定番である。ATOM S3 / ESP32-S3 の条件が全部 S 形式だったのは、そのためかもしれない（ESP32 どうしの通信用のファームウェアは手元のフォルダになく、未確認）。
- ルータに接続する STA モードでは、セカンダリチャネルはルータの動作モードに従う。2.4 GHz のルータは、周囲に重なる BSS があると 40 MHz から 20 MHz に自動で落とす（20/40 MHz 共存）。これが「測定セッション単位で形式が切り替わる」ことの説明になりうる。
- **追記（2026-11-22）:** 全条件のチャネルが分かったので確かめたところ、形式の比率はチャネルでは決まっていなかった。同じ ch1 のルータ条件でも、ほぼ S 形式の日（07/10、08/06）とほぼ W 形式の日（07/11、10/04）がある。ch1 でも 40 MHz 動作（セカンダリは上側）はできるので、この仮説とは矛盾しない。ただし、40 MHz 動作に切り替わるかどうかはチャネルではなく、その日のルータの状態（周囲の電波の混み具合など）で決まっていることになる（[10月までのデータを加えた追加解析レポート.md](10月までのデータを加えた追加解析レポート.md) 5.1 節）。
- D・WD 形式の列 0 は、どちらの並びでも**受信機の DC（中心周波数）の位置**に当たる。そのため、大きな値は LO リークなどの DC 成分かもしれない。DC 成分が残るかどうかがフレーム種別（HT / non-HT、merge の有無）で変わる、という可能性がある。**ここは推測で、検証していない。**

## 5. 帯域幅は「仕方ない」か

- **変わること自体は、ルータ任せにしている限り避けにくい。** 20/40 MHz の自動切り替えや送信レートの選択は、ルータ側で決まるからである。
- **ただし、解析上の問題は次の方法で避けられる。**

| 対策 | 内容 |
|---|---|
| 1. 記録する | `rx_ctrl` の `sig_mode`・`cwb`・`secondary_channel`・`stbc`・`mcs`・`rssi` と、`info->len`・`info->first_word_invalid` を CSI と一緒に出力する。後から確実に選別できる |
| 2. 固定する | Aterm の 2.4 GHz の設定で倍速モード（40 MHz）を切り、20 MHz に固定する。チャネルも固定にする。形式の切り替わりの大部分は止まると予想される |
| 3. CSI の設定を見直す | HT-LTF だけにしたい場合は `ltf_merge_en = false` にする。そのうえで、コールバックの中で `sig_mode == 1`（HT）以外のパケットを捨てる |

まずは 1 の記録だけを追加して短時間測ってみるのがよい。形式と `sig_mode`・`secondary_channel` の対応が分かれば、4 節の仮説をそのまま確かめられる。
