# ルータ条件におけるフレーム形式の混在と回転数識別の交絡検証

作成日: 2026-11-22
関連資料: `再現検証レポート.md`（技術メモ再現検証）の 6.3 節で挙げた懸念を検証したもの

---

## 1. 目的

技術メモの再現検証で、次のことが分かっていた。

- ルータを送信機とする条件では、パケットごとに CSI の形式（サブキャリアの配置）が異なる。
- 形式の混ざり方がクラス（回転数）ごとに違う。

クラスは回転数ごとに別々の時間帯にまとめて測定されている。そのため、分類器が回転数ではなく「その時間帯に多かったフレーム形式」を手がかりにしている可能性がある。

本レポートでは、次の 3 点を検証する。

1. フレーム形式の比率と回転数は交絡しているか。
2. 交絡しているとして、ルータ条件の高い識別精度は回転数の情報によるものか、形式の違いによるものか。
3. ルータ条件の P_dir が日によって大きくばらつく（技術メモ 6.1 節）理由は何か。

## 2. 結論

1. **交絡はあった。** 形式の比率（4 次元）だけで回転数を当てると、ルータ 8 条件で 33.7〜72.6 % の正解率になった（偶然なら 25 %）。特に 06/18・06/22・06/29・07/11 では、特定のクラスにしか現れない形式がある。
2. **それでも、ルータ条件の識別精度は形式の違いでは説明できない。** 同じ形式のパケットだけで時間平均を作ると、検証できたすべての条件で、通常の特徴量と同等かそれ以上の正解率が得られた（例: 08/03 は通常 96.2 % → S 形式のみ 98.4 %）。全クラスに共通する形式がない 06/18 でも、同じ形式をもつクラスの組の中で識別できた（0 対 3000 rpm で 99.7 %、6000 対 9000 rpm で 90.3 %）。したがって、**回転数の情報は実際に CSI に含まれている**と言える。
3. **ルータの P_dir のばらつきは、フレーム形式の比率でほぼ説明できる。** 列 0 に大きな値をもつ形式（D・WD）の比率と P_dir の相関は r = −0.958（p = 0.0002）だった。標準形式（S）のパケットだけで計算すると、ルータでも P_dir は 88〜96 % となり、ATOM S3 / ESP32-S3（約 90〜96 %）と同程度になる（06/22 の S 形式のみ 57 %。この日は S 形式のパケットがほとんどない）。技術メモ 6.1 節の「CFO/SFO の残差で CIR のピークが滲む」という推測より、こちらのほうが直接的な説明になる。

> **追記（2026-11-22）:** 10/28 までのデータを加えた追加解析で、結論 2 には制約があることが分かった。同じ回転数のセッションを時間で区切っただけの擬似クラスでも、ランダム分割で平均 70.9 % 当たる。また、日をまたぐと正解率は偶然の水準になる。そのため、単一形式テストで除けるのはフレーム形式という要因だけで、測定セッションの違いという要因は除けていない。詳しくは [10月までのデータを加えた追加解析レポート.md](10月までのデータを加えた追加解析レポート.md) の 7・9 節を参照。結論 3（P_dir と形式比率の関係）は、ルータ 14 条件でも成り立った（r = −0.955）。

### 2.1 既存の検証（`フレーム種別交絡_検証レポート.md`）との関係

同じテーマの検証が、先に `フレーム種別交絡_検証レポート.md`（`check_frametype.py`）でも行われている。本レポートはそれとは別に、独立に分類規則を立てて検証したものである。

- **一致した点:**
  - 交絡は存在する。
  - 単一の形式に絞っても、ルータ条件の識別精度はほぼ保たれる。
  - 06/18 の 4 クラス正解率は、回転数識別の根拠としては使えない。
- **本レポートで新たに加えた点:**
  - 既存レポートで「C+ 型」としていたものの多くは、列 0 に大きな値をもつ **D 形式**である。
  - この D・WD 形式の比率で、ルータの P_dir のばらつきがほぼ完全に説明できる（5.5 節、r = −0.958）。既存レポートでは P_dir を扱っていない。
- **数値の細かい違い:** 分類規則が違う（既存は 3 型、本レポートは列 0 の値も使う 4 形式）ため、数値が少しずれる。単一形式に使うファイルの下限も違う（既存は 10 パケット以上、本レポートは 20 パケット以上）。たとえば 06/22 の単一形式の正解率は、既存 94.3 %、本レポート 93.9 % である。結論に影響する差ではない。
- 形式の時間構造（1 ファイル内での混ざり方）と、W 型の並びを揃える試みについては、既存レポートを参照のこと。

## 3. フレーム形式の分類

### 3.1 見つかった形式

ルータ条件の CSI を詳しく調べると、サブキャリアの並び方が異なる形式が少なくとも 4 種類あった。次の 2 つの特徴で分類した。

- **big0**: 列 0 の振幅が 30 を超える（通常の CSI の値は 20 以下程度）
- **midnull**: 列 30〜34 がすべて 0（帯域端のヌルが配列の中央にある＝並び順が巡回している）

| 形式 | big0 | midnull | 値がある列 | 特徴 |
|---|---|---|---|---|
| **S**（標準） | なし | なし | 2〜58 の 57 本 | ATOM S3 / ESP32-S3 と同じ形式 |
| **D** | あり | なし | 0、2〜58、63 | 列 0 に 100〜160 程度の値。帯域内の振幅は S より小さい |
| **W** | なし | あり | 列 30〜34 付近を除くほぼ全列（1〜63 のうち 56 本） | 並び順が巡回した形式。同じ列番号でも周波数の割り当てが異なる |
| **WD** | あり | あり | W と同様＋列 0 | W と同じ並びで、列 0 に大きな値 |

形式ごとの平均振幅の例（06/18、08/03 の抜粋）:

| 条件 | 形式 | 列 0〜3 | 列 29〜34 | 列 56〜63 |
|---|---|---|---|---|
| 08/03 | S | 0, 0, 9.8, 10.6 | 7.6, 6.9, 6.3, 5.6, 5.3, 5.0 | 9.7, 9.2, 8.4, 0, 0, 0, 0, 0 |
| 08/03 | D | **97.1**, 0, 4.8, 4.8 | 4.1, 4.2, 4.2, 4.3, 4.5, 4.5 | 4.0, 4.0, 4.0, 0, 0, 0, 0, 8.4 |
| 06/18 | WD | **162.4**, 5.3, 7.9, 7.5 | 5.1, **0, 0, 0, 0, 0** | 10.0, 9.9, 9.8, 9.7, 9.6, 9.3, 9.1, 8.8 |

ATOM S3 / ESP32-S3 送信の 12 条件は、全パケットが S 形式だった。

### 3.2 形式の正体について

ESP-IDF の CSI は、受信したフレームの種類（non-HT / HT、STBC の有無、帯域幅、セカンダリチャネルなど）によって配列の並びや長さが変わる。ルータ（NEC Aterm WX3000HP）は応答フレームの送り方を状況に応じて切り替えていると考えられ、これが形式の混在の原因と推測される。

ただし、現在のファームウェア（`use_program/app_main_router_recv.c`）は `timestamp` と CSI の値しか出力していない。そのため、各形式がどのフレーム種別に当たるかは、このデータからは特定できない。列 0 の大きな値の意味も不明である。

## 4. 検証方法

基本的な処理は `再現検証レポート.md` と同じにした。

- XGBoost（multi:softmax、最大 300 ラウンド、早期終了 30）
- ファイル単位の層化分割（8:2 → 学習側を 8:2）
- シード 0, 1, 42 の 3 回の平均

| テスト | 内容 | 判断のしかた |
|---|---|---|
| **T1 交絡テスト** | 各ファイルの形式比率（S, D, W, WD の 4 次元）だけを特徴量にして識別 | 25 % を大きく超えれば、形式の比率がクラスの手がかりになる＝交絡あり |
| **T2 単一形式テスト** | その形式のパケットを 20 個以上含むファイルだけを使い、その形式のパケットだけで時間平均を作って識別。列はその形式で値がある列を使う（列 0 は除外） | 通常の特徴量と同程度の精度が出れば、形式に頼らず回転数を識別できている |
| **T2 の比較対象** | T2 と同じファイル集合で、(a) 通常の特徴量（全パケット・列 2〜58）、(b) 形式比率のみ | 同じ条件で比べるため |
| **追加テスト** | 06/18・06/22 で、同じ形式が現れるクラスの組の中だけで識別 | 全クラスに共通の形式がない条件のため |
| **T3 形式別 P_dir** | 形式ごとに CIR のピーク ±2 タップのエネルギー比を計算 | P_dir のばらつきの原因を調べる |

T2 は、各クラスに 20 ファイル以上残る形式だけを評価した。

- S 形式だけで計算すると、ルータでも P_dir は 88〜96 %（06/22 のみ 57 %）で、ATOM S3 / ESP32-S3 と同程度になる。

## 6. 解釈と限界

### 6.1 分かったこと

- ルータ条件の高い識別精度は、フレーム形式の違いによる見かけの精度ではない。回転数の情報は CSI に含まれている。技術メモの「ルータは短時間観測で有利」という結論の土台は崩れない。
- 一方で、ルータ条件の CSI は複数の形式の混合である。固定の列 2〜58 を全パケットに使う現在の解析では、W・WD 形式のパケットについて別の周波数の値を同じ特徴量として扱っている。直接波除去（CIR の計算）も、形式の混合のまま行われている。
  - このため、**ルータ条件の P_dir、直接波除去の結果、およびそれに基づく技術メモ 5.3・6.1 節の考察は、形式を揃えて計算し直す必要がある**。

### 6.2 この検証で否定できないこと

1. **06/18 の 4 クラス精度の内訳。** 5.4 節のとおり、形式の違いの寄与を切り分けられない。
2. **測定セッションの違いによる他の要因。** クラスごとに別の時間帯にまとめて測っているため、形式以外の時間的な変化も回転数と重なっている。人の出入り、室温、ルータの状態、他の無線機器などが該当する。単一形式テストは形式の影響を取り除くだけで、これらは取り除けない。この限界は ATOM S3 / ESP32-S3 の条件にも同じように当てはまる。
3. **形式の正体。** どのフレーム種別に当たるかは、現在のデータからは分からない（3.2 節）。

## 7. 提案

### 7.1 解析

- ルータ条件は、形式でパケットを選別してから解析する。最も単純なのは S 形式（ATOM S3 / ESP32-S3 と同じ形式）だけを使う方法である。
- W・WD 形式も使う場合は、並び順を S 形式に揃え直してから特徴量にする。列 0 の異常値も除外する。
- P_dir と直接波除去は、S 形式だけで計算し直す。

### 7.2 測定（ファームウェア）

- `app_main_router_recv.c` の出力に、受信フレームの情報を追加する。`wifi_pkt_rx_ctrl_t` の `sig_mode`（non-HT / HT など）、`mcs`、`cwb`（帯域幅）、`stbc`、`rssi`、`secondary_channel` などを、timestamp と一緒に出力しておけば、形式の正体が分かり、解析時に確実に選別できる。
- 回転数の測定順をクラスごとにまとめず、交互に（例: 0 → 3000 → 6000 → 9000 → 0 → …を短い間隔で）繰り返す。これで、フレーム形式を含むセッション単位の変化と回転数との交絡を、実験の設計段階で断ち切れる。
