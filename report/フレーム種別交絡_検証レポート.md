# ルータ条件におけるフレーム種別の交絡 検証レポート

作成日: 2026-11-22
位置づけ: [再現検証レポート.md](再現検証レポート.md) の 6.3 節で指摘した懸念の追加検証

---

## 1. 目的

技術メモ（`csi_technote_ja.pdf`）の再現では、ルータ送信の 8 条件だけ、パケットごとのサブキャリア配置（フレーム種別）が一定でないことが分かった。さらに、その比率はクラス（回転数）ごとに異なっていた。

各クラスは別々の時間帯に測定されている。そのため分類器が、回転数そのものではなく「その時間帯にルータが送っていたフレームの種類」を手がかりにしている可能性がある。本レポートでは、ルータ条件の高い識別精度が回転数の情報によるものかを検証する。

## 2. 結論

| 条件 | 交絡の程度 | 単一の型だけで識別した結果 | 判定 |
|---|---|---|---|
| 06/18 R-N→A-N | **完全**（0・3000 rpm は C+ 型、6000・9000 rpm は W 型） | 4 クラスでは評価できない | **4 クラスの結果は回転数識別の根拠にならない** |
| 06/22 R-F→A-N | 強い（0 rpm だけが W 型） | 94.3 %（全パケット 95.7 %） | 概ね問題なし |
| 06/29 R-F→A-F | 中程度（0 rpm だけ混在） | 92.9 %（同 92.3 %） | 問題なし |
| 07/11 R-F→E-F | 中程度（0 rpm だけ混在） | 83.2 %（同 82.6 %） | 問題なし |
| 07/09 R-N→E-N | 弱い | 94.0 %（同 94.5 %） | 問題なし |
| 07/10 R-F→E-N | 弱い | 99.5–99.6 %（同 99.3 %） | 問題なし |
| 08/03 R-N→A-N | 弱い〜中程度 | 98.0 %（同 97.5 %） | 問題なし |
| 08/04 R-F→A-N | 中程度 | 99.4 %（同 99.8 %） | 問題なし |

- **8 条件のうち 7 条件は、フレーム種別の情報を取り除いても精度がほとんど変わらない（差は ±1.5 pt 以内）。** これらの条件では、分類器はフレーム種別ではなく、回転数に関係する振幅の変化を捉えていると考えてよい。
- **06/18 だけは問題がある。** クラスの組とフレーム種別が完全に一致しているため、「3000 rpm と 6000 rpm を区別できたか」をこのデータでは確かめられない。この条件の 4 クラス正解率（96.4 %）を、回転数識別の根拠として使うべきではない。
- 06/18 を除いても、技術メモの「ルータ送信は短時間観測で強い」などの結論は変わらない（第 6 章）。

## 3. 方法

### 3.1 フレーム種別（サブキャリア配置）の分類

各パケットについて、64 列のうちどの列が非ゼロかを調べ、次の 3 型に分類した。

| 型 | 非ゼロの列（代表例） | 説明 |
|---|---|---|
| **C** | `2-58` | 連続した 57 本。ATOM S3 / ESP32-S3 送信のパケットはすべてこの型 |
| **C+** | `0, 2-58, 63` / `0, 2-59` など | C 型に加えて、端の列（0、63 など）にも値がある |
| **W** | `0-28, 36-63` / `1-28, 36-63` など | 中央（列 29–35 付近）が欠けていて、両端まで値がある |

判定規則は次のとおり。

- 列 30–34 がすべてゼロで、かつ列 10・40 が非ゼロなら W 型
- W 型ではなく、端の列（0, 1, 59–63）のどれかが非ゼロなら C+ 型
- それ以外は C 型

W 型は配置の形が大きく異なるので、同じ列番号でも物理的には別のサブキャリアを指している可能性が高い。

### 3.2 検証の内容

| 検証 | 内容 | 読み取り方 |
|---|---|---|
| A. 型の比率 | 条件 × クラスごとに 3 型の比率を集計 | クラス間で比率が違えば交絡の可能性あり |
| B. 時間構造 | 各ファイルが単一の型か、型がいつ切り替わるか | — |
| C. 比率だけで識別 | 各ファイルの型の比率（3 次元）だけを特徴量にして 4 クラス識別 | 偶然レベルは 25 %。高いほど、型だけでクラスが分かる |
| D. 単一型のみで識別 | 1 つの型のパケットだけで時間平均を作って 4 クラス識別（その型のパケットが 10 個以上あるファイルだけを使用） | 全パケット使用時と同程度なら、回転数の情報は型と無関係に存在する |
| E. 型内の 2 クラス識別 | 06/18 だけ。同じ型どうしのクラス（0 vs 3000、6000 vs 9000）を識別 | — |

分類器・データ分割・特徴量は、再現検証と同じ設定にした。

- XGBoost（最大 300 ラウンド、早期終了 30）
- ファイル単位の層化 8:2 分割
- 乱数シード 0, 1, 42 の 3 回の平均
- 列 2–58 の振幅の時間平均

## 4. 結果

### 4.1 型の比率（検証 A）

各クラスのパケットのうち、各型が占める割合 [%]。クラスは 0 / 3000 / 6000 / 9000 rpm の順。

| 条件 | C 型 | C+ 型 | W 型 |
|---|---|---|---|
| 06/18 R-N→A-N | 0 / 0 / 0 / 0 | **100 / 100 / 0 / 0** | **0 / 0 / 100 / 100** |
| 06/22 R-F→A-N | 0 / 0 / 0 / 0 | 8.1 / 100 / 100 / 100 | **91.9** / 0 / 0 / 0 |
| 06/29 R-F→A-F | 18.0 / 0 / 0 / 0 | 44.5 / 0 / 0 / 0 | 37.5 / 100 / 100 / 100 |
| 07/09 R-N→E-N | 0.3 / 23.3 / 0.2 / 0.4 | 99.7 / 76.7 / 99.8 / 99.6 | 0 / 0 / 0 / 0 |
| 07/10 R-F→E-N | 8.1 / 5.5 / 8.5 / 3.4 | 91.9 / 94.5 / 91.5 / 96.6 | 0 / 0 / 0 / 0 |
| 07/11 R-F→E-F | 0.7 / 0 / 0 / 0 | 27.5 / 0 / 0 / 0 | 71.8 / 100 / 100 / 100 |
| 08/03 R-N→A-N | 51.2 / 64.4 / 76.3 / 98.9 | 48.8 / 35.6 / 23.7 / 1.1 | 0 / 0 / 0 / 0 |
| 08/04 R-F→A-N | 53.4 / 95.4 / 55.7 / 99.3 | 46.6 / 4.6 / 44.3 / 0.7 | 0 / 0 / 0 / 0 |

ATOM S3 / ESP32-S3 送信の 12 条件は、全パケットが C 型である。つまり、この問題はルータ送信の条件にしか存在しない。

### 4.2 時間構造（検証 B）

**ファイル内で型が混ざることはほとんどない。** 1 つの型が 95 % 以上を占めるファイルの割合は、どの条件でも 92–100 % だった。

| 条件 | 06/18 | 06/22 | 06/29 | 07/09 | 07/10 | 07/11 | 08/03 | 08/04 |
|---|---|---|---|---|---|---|---|---|
| 単一型ファイルの割合 [%] | 100.0 | 100.0 | 96.2 | 97.0 | 92.4 | 99.7 | 98.7 | 99.1 |

型は、**測定の途中のある時点でまとめて切り替わる**。0 rpm クラスのファイルを測定順に並べ、主な型を追うと次のようになる（P = C+ 型、×の後はファイル数）。

| 条件 | 0 rpm クラス内での主な型の並び | その後のクラス |
|---|---|---|
| 06/22 | C+ ×40 → **W ×460** | すべて C+ 型 |
| 06/29 | C+ と C が交互に 9 区間（計 312 ファイル）→ **W ×188** | すべて W 型 |
| 07/11 | C+ ×131 → C ×3 → C+ ×7 → **W ×359** | すべて W 型 |

ルータは、測定の途中で送信フレームの種類を変えている。考えられる原因は、変調方式の自動切り替えやアンテナ構成の変更など、ルータ内部の状態変化である（このデータからは特定できない）。この切り替わりの時点が、たまたまクラスの境界と重なったと考えられる。

### 4.3 比率だけで識別（検証 C）

| 条件 | 型の比率のみ [%] | 全パケットの振幅（通常の解析）[%] |
|---|---|---|
| 06/18 | 50.4 ± 0.1 | 96.4 ± 0.8 |
| 06/22 | 48.8 ± 0.5 | 95.7 ± 1.0 |
| 06/29 | 42.3 ± 0.4 | 92.3 ± 0.5 |
| 07/09 | 39.5 ± 0.5 | 94.5 ± 0.5 |
| 07/10 | 36.3 ± 1.4 | 99.3 ± 0.2 |
| 07/11 | 31.8 ± 0.4 | 82.6 ± 1.0 |
| 08/03 | 36.2 ± 0.5 | 97.5 ± 0.4 |
| 08/04 | 53.4 ± 1.0 | 99.8 ± 0.2 |

どの条件でも偶然レベル（25 %）を上回っている。つまり、**型の比率にはクラスの情報が多少含まれている**。

06/18 の 50 % は、「{0, 3000} と {6000, 9000} の 2 組は完全に分かるが、組の中は区別できない」という状態に相当する。ただし通常の解析の精度（82–99 %）には遠く及ばないので、型の比率だけで今回の精度を説明することはできない。

### 4.4 単一型のみで識別（検証 D）

| 条件 | 使用した型 | 使用ファイル数（0 / 3000 / 6000 / 9000 rpm） | 正解率 [%] | 全パケット使用時 [%] |
|---|---|---|---|---|
| 06/22 | C+ | 41 / 500 / 500 / 500 | 94.3 ± 0.4 | 95.7 |
| 06/29 | W | 188 / 500 / 500 / 500 | 92.9 ± 1.6 | 92.3 |
| 07/09 | C+ | 500 / 422 / 500 / 500 | 94.0 ± 0.4 | 94.5 |
| 07/10 | C | 204 / 165 / 158 / 224 | 99.6 ± 0.6 | 99.3 |
| 07/10 | C+ | 490 / 490 / 486 / 498 | 99.5 ± 0.0 | 99.3 |
| 07/11 | W | 360 / 500 / 500 / 500 | 83.2 ± 2.0 | 82.6 |
| 08/03 | C | 424 / 414 / 471 / 500 | 98.0 ± 0.8 | 97.5 |
| 08/03 | C+ | 407 / 318 / 233 / 255 | 91.1 ± 1.4 | 97.5 |
| 08/04 | C | 456 / 487 / 361 / 499 | 99.4 ± 0.3 | 99.8 |
| 08/04 | C+ | 378 / 260 / 290 / 53 | 93.1 ± 1.3 | 99.8 |

単一の型に絞ると、型の違いという手がかりはなくなる。それでも主要な型では、精度が全パケット使用時とほぼ同じになった。したがって、これらの条件の精度は回転数の情報によるものと考えられる。

C+ 型に絞った 08/03・08/04 で精度が下がるのは、使えるファイル数とパケット数が少ないためと考えられる。

06/18 は、どの型でも 2 クラス分のファイルしか存在しないため、4 クラスでは評価できない。

### 4.5 06/18 の型内 2 クラス識別（検証 E）

| 比較 | 型 | 正解率 [%]（偶然レベル 50 %） |
|---|---|---|
| 0 rpm vs 3000 rpm | C+ | 99.3 ± 0.6 |
| 6000 rpm vs 9000 rpm | W | 90.8 ± 2.9 |

同じ型どうしなら回転数を区別できているので、06/18 にも回転数に関係する情報は含まれている。しかし、**3000 rpm と 6000 rpm のように型をまたぐ組は、型の違いと回転数の違いを切り分けられない**。

### 4.6 型の配置をそろえる試み（不成立）

W 型が C 型の列を巡回的にずらしたものなら、ずらし直せば同じ特徴量として扱える。そこで、同じクラス（0 rpm）の中で両方の型の平均振幅の形を比べ、最も一致するずらし量を探した。

| 条件 | 最も一致したずらし量 | 相関係数 |
|---|---|---|
| 06/22 | 5 | 0.30 |
| 06/29 | 63 | 0.63 |
| 07/11 | 37 | 0.84 |

ずらし量が条件ごとにばらばらで、相関も低い。W 型は単純な並べ替えではなく、別のフレーム形式（たとえば HT ではないレガシー形式）である可能性がある。この方法による補正は採用しなかった。

## 5. 06/18・06/22 についての補足

この 2 日分は、インデックス列のない古い出力形式（129 列）で記録されている（再現検証レポート 3.2 節）。C+ 型の配置も `0, 2-59` で、他の日の `0, 2-58, 63` と微妙に異なる。

技術メモではこの 2 日分が 1 列ずれて読み込まれていた疑いもある（同 6.1 節）。データ形式と測定時のルータの状態の両方に問題を抱えた 2 条件と言える。

## 6. 技術メモと再現結果への影響

ルータ送信のグループ平均（再現値）から 06/18 を除いても、結論は変わらない。参考として、型の問題が大きい 06/18 と 06/22 の両方を除いた値も示す。

| 指標 | ルータ 8 条件の平均 | 06/18・06/22 を除く 6 条件の平均 |
|---|---|---|
| 時間平均の正解率 | 94.7 % | 94.3 % |
| 観測時間 0.05 s の正解率 | 84.1 % | 84.2 % |

- 「時間平均が有効」「短時間観測ではルータ送信が最も強い」という技術メモの結論は、交絡があっても成り立つ。
- ただし **06/18 の 4 クラスの値**は、回転数識別の根拠から外すか、少なくとも注記が必要である。
  - 該当箇所: 技術メモ付録 A・C、図 7・9・10、再現検証レポートの付録。

## 7. 限界と今後の提案

1. **今回取り除けたのは「フレーム種別」という 1 つの交絡だけである。** クラスごとに測定の時間帯が分かれているため、室内環境のゆっくりした変化（人の出入り、温度、他の端末の通信）など、型以外の時間的な違いが分類に使われている可能性は残る。これは ATOM S3 / ESP32-S3 の条件にも共通する。
2. 測定設計の改善案:
   - 回転数を **短い間隔で交互に切り替えながら測定する**（例: 0 → 3000 → 6000 → 9000 → 0 …を数分ごとに繰り返す）。こうすると時間的な違いとクラスが重ならない。
   - 既存データでも、「測定順で前半を学習・後半をテスト」に分割する評価を追加すれば、時間的な違いの影響の大きさをある程度見積もれる。
3. ルータを送信源にする場合は、CSI と一緒に **フレームの種類（`rx_ctrl` の `sig_mode`、`mcs`、`cwb` など）を記録する**。そうすれば解析時に型をそろえられる。現在の `app_main_router_recv.c` はこれらを出力していない。
4. W 型の正体（どのフレーム形式か）は、上記 3 の記録がないと特定できない。
